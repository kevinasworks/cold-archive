## 使用

打开自行构建的本地验证 `.app`（新版独立保留，不替换运行中的旧版）。选择单个文件、多个文件或一个文件夹，填写归档名称并选择保存位置；检测来源元数据后，依次确认类别、设备、软件、用途、备注。最后一项确认后自动运行全部归档阶段，成功后可在 Finder 显示结果。

自定义来源信息提供中英两个输入框。macOS 15+ 默认自动双向翻译：最后编辑的一栏作为原文，停止输入约半秒后自动填入另一栏；关闭自动翻译可独立手动填写。正文使用 Apple 本机翻译，首次可能需要下载系统语言包。macOS 14 保留手动填写。未知值与无补充是明确选择，不会自动代填。元数据读取遍历所有纳入归档的文件，没有抽样数量或单文件读取时限，也没有设备/软件标签白名单。请求 ExifTool 可读取的全部元数据标签，并结合独立格式识别、媒体、文档属性、文件系统与扩展属性读取器；保留原始分组与逐文件记录。已分类的二进制元数据保留原值，缩略图、像素等内容载荷不导出，未分类二进制仅记录长度、哈希和未解码状态；损坏、加密、工具不支持或权限不足的部分会单独报告。完整报告走文件通道，不受日志截断限制，可从来源表单单独导出。固定归档排除规则不变。

## 运行要求与交付范围

- macOS 14 或更新版本；当前 `dist` 构建为 Apple Silicon arm64。
- 完整本地构建会内置 Python、Perl、7-Zip、ExifTool、FFprobe、MediaInfo、Siegfried/PRONOM 及文档元数据依赖。公开仓库不含这些预编译运行时，使用构建脚本在本地准备。运行已构建应用不需要 Homebrew 或原技能目录。
- 元数据与归档离线运行。Apple 自动翻译的首次语言包下载是独立的系统要求。
- 本地验证包跳过外层 Apple 签名，内部 Mach-O 使用 ad-hoc 签名；未做 Developer ID 签名或 Apple 公证。已验证本机迁移路径及禁止网络运行，尚未在另一台实体 Mac 验收；Intel Mac 不在本构建支持范围内。
- 当前桌面功能覆盖创建归档。已有归档的独立检查/恢复工具没有另设图形工作区，恢复方法随每个归档的 README 提供。

## 源码公开检查

```sh
python3 -B scripts/public-source.py --list
```

公开文件清单排除预编译工具、运行时、安装包、缓存、个人签名配置及历史日志。引擎来源已由用户确认，并已纳入 GPL-3.0-only 范围；检查只针对拟公开文件，不把未上传运行时的待核问题自动作为源码阻塞。源码编译的第一步可运行 `CLANG_MODULE_CACHE_PATH="$PWD/.build/clang-cache" swift build --disable-sandbox`；完整本地应用还需准备锁定版本运行时，现有 `scripts/build-native-tools.py` 与 `scripts/build-perl.py` 继续保留。固定依赖输入由 `scripts/runtime-sources.json` 锁定；`python3 -B scripts/fetch-runtime.py` 只核验本地缓存，增加 `--fetch` 才从官方固定版本下载并核对 SHA-256，不执行安装或升级。第三方预编译工具可下载到本地构建目录，但不会进入公开源码集合。已在仅含拟公开源文件的临时目录中，用已核验原始缓存重新构建运行时和完整本地验证 `.app`；未使用原工作目录的预编译运行时。固定输入的全新网络下载尚未逐一验证，不以缓存构建结果代替网络可用性证明。

## 保留的归档保障

归档核心保留原始快照；桌面元数据读取器按 2026-10-03 用户要求改为全量模式，位于 `Sources/ColdArchive/Resources/Engine`。固定压缩参数、排除规则、SHA-512 清单、真实解压恢复、空目录比较、源数据复核、双语文档、独占发布与发布后验证均由完整引擎执行。不得只完成压缩就报告成功。

桌面适配器 `desktop_bridge.py` 增加安全取消检查点与 JSON 完成事件；取消时先停止 7-Zip 子进程，再由引擎清理暂存和恢复目录。哈希每块可响应取消；目录枚举、文档生成及底层文件系统 I/O 可能需要完成当前操作后响应。发布已完全验证并提交之后才到达的取消不会删除成功的归档。程序不阻止系统强制终止或断电；这些情况不等同于正常取消，可能留下隐藏工作目录，不能视为成功归档。

来源确认记录只在本机临时目录中短暂保存并在结束时清理。输出归档内按格式保留用户提交的来源信息、原路径与检测证据。所有归档参数通过独立进程参数传递，不经过 shell。

## 构建和验证

构建主机需要 macOS Apple Silicon、Xcode / Swift 6 工具链、make 和支持 `tarfile.data_filter` 的 Python（推荐 3.12+）。不自动安装开发工具，也不更改应用声明的最低 macOS 14。

首次在干净源码目录中准备运行时；下列下载只落到本地忽略目录，不会进入 GitHub 源码集合：

```sh
python3 -B scripts/prepare-runtime.py --prepare --fetch
```

已有全部固定版本归档缓存时可省略 `--fetch`。该流程构建 7zz、FFprobe 和 Perl，展开 Python、ExifTool、Archive::Zip、Siegfried，并仅展开 MediaInfo 包而不执行安装器。现有可执行运行时存在时会拒绝覆盖；当前工作目录无需重复执行。新构建二进制的哈希需要重新审核，脚本不会静默改写正式发行基线。

然后在项目目录运行：

```sh
COLD_ARCHIVE_LOCAL_BUILD=1 ./scripts/build-app.sh
./scripts/test.sh
```

以上命令生成独立标记的本机验证包，跳过外层 Apple 签名。正式发行使用 `./scripts/build-app.sh`，该命令在第三方许可或对应源码材料缺失时终止。项目原创代码及自用技能衍生引擎采用 GPL-3.0-only。参见 [第三方组件与许可证](THIRD_PARTY_NOTICES.md)。

不需要第三方 Swift 包；发行构建要求 `vendor/runtime` 中已准备好固定版本组件，依赖下载和构建记录在 `vendor` 与 `scripts` 中。也可直接用 Xcode 打开 `Package.swift`。应用资源按标准 `.app/Contents/Resources/Engine` 路径加载；开发运行使用 SwiftPM 资源包。

`QA/Fixture` 是专门创建的合成测试源，`QA/Output` 中的归档用于实际 GUI 流程验收，不包含用户原始资料。旧 QA 验收日志仅在本地保留，不属于拟公开源码集合。

五步表单新增“返回上一步”（第一步禁用）。已确认答案与当前未提交草稿、选择方式、中英文本及翻译模式保留；返回修改后逐步重新确认，最后一步确认才开始归档。翻译未完成的草稿恢复后重新请求翻译，旧请求失效。新增回退修改、保留后续答案及禁止提前发布测试。未进行本轮完整 GUI 点击验收。

## 1.1.3 Esc 取消来源确认

五步来源确认均支持 Esc，行为与“取消”一致：关闭确认窗口、清空本轮确认，返回主界面，不开始归档。已选文件和保存位置保留。

## 1.1.4 未知与不填写分离

前四项确认分别提供“未知（不清楚此项信息）”及“不填写（不提供此项信息）”。保存为独立 unknown 与 not_provided 状态；双语文档分别显示“不清楚 / Unknown”和“未提供 / Not provided”。备注继续使用“无补充”或自由填写。旧的合并答案仅保留读取兼容，新界面不再生成。

## 1.1.5 错误提示与位置冲突

归档目录冲突后，在本轮清理结束后直接打开独立的文件夹选择窗口，选择其他位置并重试，保留五项来源确认；取消不重试，同一路径不自动重复执行。现有防覆盖检查保留，不通过删除旧归档解决冲突。

错误提示改为有标题栏的可移动独立窗口，简要说明原因和处理办法。已识别目录冲突、空间不足、访问权限、源数据变化；无法归类的错误明确说明原因尚未确定，日志留在主界面执行记录。本轮自动化验证错误分类、历史成功日志不误判、简短输出及既有流程；未以用户实际录像触发重试，也未实测新版窗口拖动。

## 1.1.6 批量确认分组与多选

五项确认共享紧凑布局，读取问题移入独立详情页并按原因汇总；默认不展开文件列表。类别、设备、软件候选按字段、值、译文和证据性质分组，格式关联按品牌、角色、状态、依据分组，复选框支持多选、全选和清空，不默认勾选。每组显示唯一文件数，可展开完整依据；长列表仅在固定区域滚动，底部按钮保持可见。用途及备注保持用户填写。

提交保留选中组的全部文件映射、字段依据及格式线索的设备未确认说明；缺少译文时禁止直接提交，可带入自定义填写补全。返回上一步保留勾选和草稿。29 项 Swift 测试通过，包括 309 条同类证据压缩为一组、末条证据保留、警告汇总及不同文件范围隔离。本轮未用用户实际 309 文件重跑读取或完成 GUI 点击验收。

## 1.1.7 按文件组逐组确认

替代 1.1.6 的候选多选模式。五项按“文件类别 + 当前问题的检测结果”分别划分文件组，每组使用原有的采用检测结果、自定义填写、未知、不填写（备注为无补充）操作。每个文件在一项中只归属一个组，缺少检测结果的文件单独保留，冲突检测值要求手动确认；每组独立保存中英文答案与文件映射。用途和备注不从元数据推断，按文件类别填写。

支持跨组返回和草稿恢复；最后一个问题的最后一组确认后才开始归档。新版来源回答协议为 schema 3，旧 schema 2 继续可读，冷归档目录格式不变。归档前验证每一项的组是否覆盖当前全部文件，拒绝漏项、重复、外来文件和未确认答案。详见 QA/VALIDATION-1.1.7.md。


## 2.0.11 读写调度整改

智能读取与写入根据实际观测进行探测、比较收益、回退和再探测；工程上限为64，实际额度还受内存、文件描述符和待处理任务限制。设置数量、调度目标、共享额度与实际活动数分别记录。自定义数量仍是全应用上限，资源保护时显示原因，资源恢复后自动恢复；降低额度不终止已有文件。

所有任务共享读取与目标写入许可，同一存储设备协调读写探测，不同设备分别保留写入反馈。只有身份确认的NAS地址别名会合并。NAS辅助数据过期/缺失时使用本机反馈，不把NAS总流量当成本软件的速度；读、写分别使用各自的SMB延迟。

本机临时文件保留独立额度。暂停在安全检查点释放已闲置的额度和等待登记，恢复时重新申请；取消仍按原引擎事务清理。归档准备、元数据导出和许可等待在后台执行。7z的一个输出流仍是一个写入任务，上限提高不会凭空拆成多个归档输出。

观测明确区分实际逻辑字节、内核进程树计数和归一化完成工作量；计量失败会标记并记录，不把成功数据写入改判成失败。性能对照为显式运行的测试：`SchedulerBenchmarkTests`、`WriteBenchmarkTests`；常规完整回归另覆盖共享额度、暂停恢复、完整性和错误恢复。阶段性数据与适用范围见`Research/2026-11-03-智能调度本机验收记录.md`。


### 2.0.12：钥匙串授权与签名

- 固定Apple团队及应用签名身份，构建不再自动退回临时签名。
- SNMP凭据使用新版独立钥匙串条目。旧授权不兼容时在SNMP设置重新填写原密码并保存一次，旧条目保留，后台不反复弹出旧授权。
- 验证记录见[2.0.12验收](QA/VALIDATION-2.0.12.md)。现有Apple Development签名用于本机维护；公开分发需另行准备Developer ID及公证。
- 其他构建机需提供同团队有效证书，可通过COLD_ARCHIVE_SIGN_IDENTITY指定证书SHA-1；缺少固定身份时构建停止。不要提交或导出私钥来绕过签名检查。


### 2.0.13：队列取消/删除后可继续新建
